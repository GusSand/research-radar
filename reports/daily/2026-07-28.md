## 01 · [ParityTransformer: Interpretability by Design via the Deep Parity Bottleneck](https://arxiv.org/abs/2607.20652)

`mech-interp` `preprint` — arXiv, July 2026

Interpretability in transformers is almost always post-hoc — you train the model first, then reverse-engineer what it learned. ParityTransformer inverts the workflow: it forces an interpretable constraint during training via the Deep Parity Bottleneck (DPB), and the features that emerge match SAE-discovered features on probing benchmarks while substantially outperforming them on every causal metric — absorption, steering, and intervention stability.

![Figure 1: DPB vs standard SAE across interpretability metrics — absorption rate, steering accuracy, and causal stability](https://arxiv.org/html/2607.20652/x1.png)

*Figure 1: DPB achieves lower feature absorption (12% vs 28%), higher steering accuracy (74% vs 61%), and higher causal intervention stability (71% vs 56%) vs standard SAEs. Probing performance is equivalent — the gains are entirely on causal metrics.*

The Deep Parity Bottleneck partitions the residual stream into parity-signed feature subspaces during training, enforcing that each feature's causal role is legible by construction rather than recovered post-hoc. Evaluated on GPT-2 and Pythia-1.4B against Anthropic JumpReLU and standard TopK SAEs, DPB models match SAE performance on token-type probing but show substantially lower feature absorption rates, higher steering accuracy, and more stable causal intervention outcomes across depth and model scale — with no significant capability degradation.

## 02 · [The Language of Security: How Prompt Syntax Shapes Code Vulnerability in LLMs](https://arxiv.org/abs/2607.15937)

`AI security` `peer-reviewed` `ICSME 2026` — arXiv, July 2026; accepted ICSME 2026

Security prompts aren't just about content — the syntactic form of the instruction matters as much as the instruction itself. The same security requirement reformulated across five syntactic variants produces up to a 31 percentage-point swing in CWE violation rates, a gap large enough to render prompt engineering the primary security control in LLM-assisted coding workflows.

![Figure 1: CWE violation rate across 5 syntactic prompt formulations on 5 LLMs](https://arxiv.org/html/2607.15937/x1.png)

*Figure 2: Declarative instructions produce 58% CWE violation rate; constraint-based formulations reduce this to 23% — a 31 pp swing from syntax alone, averaged across GPT-4o, Claude 3.7 Sonnet, Gemini 2.0 Flash, Mistral Large, and Llama 3.3 70B.*

Across five major LLMs, 100 coding prompts, and 14 CWE categories, the authors found that declarative and imperative styles consistently underperform role-based and chain-of-thought instructions by 20–31 pp on high-risk CWEs including CWE-89 (SQL injection) and CWE-79 (XSS). Critically, the interaction between model and syntactic variant is significant — a formulation that elicits secure code from GPT-4o may be among the worst choices for Llama 3.3 70B. Accepted to ICSME 2026.

**03 · [The Illusion of Secure LLM Code: How Iterative Reprompting Undermines Security](https://arxiv.org/abs/2607.23710)**
`AI security` — arXiv, ~July 26, 2026
![Critical security issues increase by +37.6% over 5 reprompting iterations in agentic coding](https://arxiv.org/html/2607.23710/x1.png)
*Figure 4: Cumulative critical security issue increase across reprompting iterations. Initial outputs appear safe; each agentic refinement adds security regressions driven by functionality objectives superseding security constraints.*
Most LLMs produce low-risk code on an initial request, creating an illusion of security. Iterative reprompting in agentic workflows — optimising for stated functional goals — causes critical CWE violations to increase by +37.6% after 5 iterations as the model trades security constraints for the more recently specified functionality objectives.

`AI security` — arXiv, July 2026

- **Interpretability-by-design (#1):** ParityTransformer is the first work to demonstrate that an architectural constraint applied during training produces features that causally outperform post-hoc SAEs on every metric except probing — where they are equivalent. If the result holds across further evaluations, it marks a potential shift away from the post-hoc SAE-centric mech-interp programme. Flagged for weekly roundup.
- **Peer-reviewed count:** Language of Security (#2, ICSME 2026 main track) is the sole peer-reviewed item today. Remaining nine are preprints.
- **dLLM jailbreak cluster:** PAD (#3) joins MaskForge (Jul 24) and DIJA (Jul 25) as the third distinct dLLM jailbreak framework in five days, each targeting a different structural property — MaskForge exploits mask-text template structure, DIJA exploits bidirectional context commitment, PAD directly disrupts alignment-critical attention heads. The bidirectional attention mechanism is the most-studied attack surface in dLLM research this week.
- **LACUNA (#9) methodology note:** The ≤30% localization bound is measured against a benchmark with *known ground-truth* parameter locations. The output-localization gap has been assumed but not previously measured with this specificity; the result suggests output-based success metrics are uninformative for evaluating mechanistic claims.
- **Security agentic cluster (#4, #7):** Illusion of Secure Code (#4) and LogInject (#7) both target agentic deployment — iterative reprompting pipelines and SOC automation respectively. Neither uses novel jailbreak techniques; both exploit standard operational patterns.
- **Weekly roundup nominations:** #1 (ParityTransformer — interpretability-by-design), #2 (prompt syntax × code security, ICSME 2026), #3 (PAD — dLLM attention disruption jailbreak), #9 (LACUNA — localization gap).
